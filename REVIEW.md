# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient` initialization (line 22) | Missing `tz_aware=True` on `MongoClient`. PyMongo returns offset-naive datetimes by default, causing timezone comparisons against aware IST datetimes to raise `TypeError`. | Subtracting or comparing stored datetimes against aware datetimes raises `TypeError: can't compare offset-naive and offset-aware datetimes`. | Passed `tz_aware=True` to `MongoClient` and consistently handled UTC datetimes and IST conversions at API boundaries. |
| 2 | `compute_late_minutes` (lines 33–37) | (a) Replaced hour/minute on UTC `punch_in` directly with IST shift times without timezone conversion. (b) Grace period logic `minutes > 10` where `minutes = int(total_seconds / 60)` erroneously returned 0 for elapsed times between 10:01 and 10:59 (e.g. 10:30 gives `int(630/60) = 10`, `10 > 10` is False -> 0 instead of 10). (c) Failed to handle overnight shifts (punch-in before shift end belongs to previous day's shift). (d) Did not truncate instants to whole seconds (R1). | Shift 09:30, punch-in at 09:40:30 returns 0 late minutes instead of 10. Overnight shift (22:00–06:00) punch-in at 00:30 IST compares against today's 22:00, resulting in negative difference. | Converted punch-in to IST, anchored shift start to record's attendance date, checked strictly `diff_seconds > 600`, floored whole elapsed minutes `int(diff_seconds // 60)`, and truncated instants to whole seconds. |
| 3 | `compute_work_hours` (lines 40–41) | Used standard Python `round()`, which applies banker's rounding (round half to even) rather than standard half-up rounding required by R4. | A work duration of 2.525 hours rounds to 2.52 instead of 2.53. | Used `decimal.Decimal` with `ROUND_HALF_UP` (`hours.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`). |
| 4 | `compute_overtime` (lines 44–48) | (a) Subtracted naive datetime from aware datetime (crashes). (b) Anchored `end` on `date_str` for overnight shifts instead of the next calendar day. (c) Missing the R3 minimum 30-minute threshold (returns overtime even for < 30 minutes). | Punch-out 15 minutes after shift end returned 15 instead of 0. For overnight shifts (22:00–06:00), `end` was set 24 hours too early, giving massive incorrect overtime. | Enforced timezone awareness, added 1 day to `end_dt` when `shift_end <= shift_start`, and returned whole minutes only when `>= 30`, otherwise 0. |
| 5 | `health` endpoint (lines 72–74) | Returns 200 unconditionally without pinging MongoDB, violating the contract requirement to return 503 when MongoDB is unreachable. | Stop MongoDB service; `GET /health` still returns 200 instead of 503. | Added `client.admin.command("ping")` in a try/except block; raises `HTTPException(503, "MongoDB unavailable")` on failure. |
| 6 | `create_employee` (lines 77–85) | (a) Check-then-insert (`find_one` then `insert_one`) allows duplicate `emp_code` creates under concurrency. (b) Missing schema validation for `emp_code` regex (`^EMP\d{4,6}$`), email format, string lengths, and `shift_start != shift_end`. (c) Returns `created_at` as Python datetime string instead of epoch milliseconds. | Concurrent duplicate creates both return 201; creating an employee with `shift_start == shift_end` succeeds; response `created_at` fails OpenAPI schema validation. | Created unique index on `emp_code`, caught `DuplicateKeyError` returning 409. Added Pydantic field validators and regex patterns. Formatted `created_at` as integer epoch milliseconds. |
| 7 | `list_employees` (lines 88–96) | (a) Off-by-one pagination error: `skip = page * page_size` skips the first page entirely (page 1 returns items 21–40). (b) `total` counts entire collection `count_documents({})` instead of filtered set `q`. (c) Missing sort by `emp_code` ascending. (d) Returns `created_at` as BSON datetime instead of epoch milliseconds. (e) Missing `page_size` max limit (max 100). | `GET /employees?page=1` skips page 1; `GET /employees?department=Engineering` returns total count of all departments in the DB. | Set `skip = (page - 1) * page_size`, computed `total = db.employees.count_documents(q)`, added `.sort("emp_code", 1)`, enforced `page_size <= 100`, and formatted `created_at` as epoch milliseconds. |
| 8 | `punch_in` (lines 99–122) | (a) Check-then-insert allows duplicate punch-ins under concurrency. (b) Crash on unknown employee: `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable` (500) instead of 404. (c) Date attribution uses host local timezone `ts.date().isoformat()` instead of IST calendar date and overnight shift rules (R1). (d) Missing timestamp truncation and validation (`punched_at` lacks epoch millisecond bounds and strict type). (e) Injects internal `id` into response and returns `punch_in` as BSON datetime. | Punching in with non-existent `emp_code` returns 500. Concurrent punch-ins for the same date both succeed. Overnight punch-in before shift end attributed to current date instead of previous day. Response contains forbidden `"id"`. | Verified employee exists returning 404; created unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` returning 409; implemented R1 IST overnight date attribution; truncated timestamps to whole seconds; strictly validated inputs; formatted response without `id` and converted `punch_in` to epoch milliseconds. |
| 9 | `list_attendance` (lines 124–151) | (a) Memory leak & performance defect: loads entire collection into memory with `list(db.attendance_logs.find(q))` and sorts in Python, causing latency spikes and OOM on 100k records. (b) Incomplete sort: only sorts by `date` desc, omitting secondary sort `emp_code` asc. (c) Missing validation: `date_from > date_to` returns 200 instead of 422. (d) Injects internal `id` into response and fails to supply required defaults (`history: []`, `half_day: False`) for legacy records. | Memory spikes to gigabytes on 100k docs; `date_from=2026-07-20&date_to=2026-07-10` returns 200 instead of 422; response contains `"id"`. | Replaced in-memory loading with index-backed MongoDB cursor `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`; added `date_from <= date_to` validation returning 422; formatted documents to match `AttendanceRecord` schema with proper epoch milliseconds and defaults. |
| 10 | Application startup (indexes missing) | Starter defines zero database indexes. Without indexes, list and analytics queries perform collection scans (`COLLSCAN`), and uniqueness cannot be enforced under concurrency. | Database explain shows `COLLSCAN` on all queries; concurrent creates and punch-ins produce duplicate records. | Implemented FastAPI `lifespan` handler calling `init_indexes()` to idempotently create all unique and compound indexes at startup. |

Also note anything you looked at and decided was **not** a defect, and why:
1. **Fixed IST timezone offset**: `IST = timezone(timedelta(hours=5, minutes=30))` is not a defect because Indian Standard Time does not observe Daylight Saving Time (DST); a fixed offset is accurate year-round.
2. **Calendar dates and shift times stored as strings**: Storing `date` as `"YYYY-MM-DD"` and shift times as `"HH:MM"` in MongoDB is not a defect; it adheres strictly to the data model specification, avoiding artificial timezone conversions and daylight distortions on calendar days and wall-clock times.
